# 个人职业操作系统：V0.2 启动蓝图

当前仓库已包含可运行的本地首版：React 页面、FastAPI API 和 SQLite 持久化。以下“本地运行”部分以实际代码为准；之后的产品蓝图说明页面和能力边界。

## 技术栈

- 前端：Vite + React + TypeScript + 原生 CSS
- 后端：Python FastAPI + Pydantic + uvicorn
- 数据：本机 SQLite，默认位置 `data/career-os.db`
- 包管理器：uv（Python）与 Bun（前端）

## 环境要求

- Python 3.11+
- [uv](https://docs.astral.sh/uv/)
- [Bun](https://bun.sh/)

## 安装配置

```bash
cp .env.example .env
./start.sh
```

默认 `START_MODE=dev`：前端使用 Vite，后端启用自动重载。稳定模式会先构建前端，再由 FastAPI 在同一端口托管：

```bash
START_MODE=stable ./start.sh
```

- 前端：`http://127.0.0.1:6401`
- 后端健康检查：`http://127.0.0.1:6400/health`
- 日志：`logs/backend.log`、`logs/frontend.log`

首次启动会安装依赖，并把当前 Demo 的示例内容写入本地 SQLite。要获得空白数据，删除 `data/career-os.db` 后重新启动；这会删除本机数据。

## 停止

```bash
./stop.sh
```

## 测试与构建

```bash
uv run pytest
cd frontend && bun run build
```

## 配置项

`.env` 只用于本机，不应提交。

| 变量 | 默认值 | 说明 |
|---|---:|---|
| `HOST` | `127.0.0.1` | 首版只允许本机访问 |
| `BACKEND_PORT` | `6400` | FastAPI 端口 |
| `FRONTEND_PORT` | `6401` | Vite 开发服务器端口 |
| `START_MODE` | `dev` | `dev` 使用 Vite；`stable` 使用 FastAPI 托管构建产物 |
| `DATABASE_PATH` | `data/career-os.db` | 本地 SQLite 文件 |
| `ENABLE_DEEPSEEK_AGENT` | `false` | 显式开启项目内 DeepSeek 编码 Agent |
| `DEEPSEEK_API_KEY` | - | DeepSeek 密钥，只放 `.env`，不提交 |
| `DEEPSEEK_AGENT_TIMEOUT_SECONDS` | `600` | 单次编码任务最大运行秒数 |

项目结构和数据流见 [CODE_ARCHITECTURE.md](CODE_ARCHITECTURE.md)，架构决策与验证映射见 `documentation/`。

## DeepSeek 编码 Agent

项目内已锁定官方 `dsh` 运行时。复制 `.env.example` 后添加：

```dotenv
ENABLE_DEEPSEEK_AGENT=true
DEEPSEEK_API_KEY=replace-with-your-key
```

启动系统后，在“设置与导出”的 **DeepSeek 编码 Agent** 面板提交代码任务。它只运行在本仓库工作区，`data/`、`.env`、日志和 PID 会被隔离；可选择本次明确授权的职业资料作为背景。完整安全边界和已知网络限制见 `documentation/automation.md`。

“目标岗位”页面的 AI 匹配使用同一份密钥，但不启动 CLI：手动粘贴 JD、勾选项目和允许 AI 使用的资料后，再点击“开始一次 AI 匹配分析”。它不会自动抓取招聘网站、投递职位或在后台定时调用模型。默认模型为 `deepseek-chat`；若你的服务商要求其他模型，在 `.env` 设置 `DEEPSEEK_MODEL` 后重启。

## 先定一句话

这是一个**个人职业操作系统**：它是 Get、Notion、Obsidian 等资料来源之上的职业视图层，不是万能的 AI 助手、聊天应用或第四个笔记库。

它帮助我纵观过去的经历和信息项目、现在的职业身份与能力主线，以及未来的职业计划；真实资料仍保留在原来的笔记库、项目文档或本地文件中。

## V0.2：项目接入与电子简历

当前 Demo 已增加一条最小闭环：`新建项目 -> 关联职业资料 -> 手动选择可展示 -> 生成电子简历`。项目默认私密；只有标记为“可展示”的项目才会进入面试展示页。电子简历可以打印为 PDF，也可以复制包含公开简历数据的展示链接。

同时增加“职业 Git”：每次只提交一个能力变化（变化前、变化后、关联项目与日期）。它记录真实项目带来的成长，不做能力打分或复杂知识图谱。

职业项目、资料和分析数据保存在本机 SQLite；电子简历的编辑正文、模板和头像暂保存在当前浏览器。设置页的“完整备份”会把两部分数据合并为一个 JSON 文件。展示链接不含原始资料，只包含你已选择公开的简历信息和项目内容，拿到链接的人都可查看它。

V0.1 的成功不是页面数量，而是能把 3 个过去或当前项目、4 条能力主线和 1 份职业计划关联起来，并持续维护来源。

## 终局与当前版本

终局：从可信的个人职业资料中，持续形成项目案例、职业时间线、能力地图、学习路径、技术文章和简历草稿。

V0.1：只跑通下面这条“资料进入职业地图”的路。

```text
职业资料（经历 / 项目文档 / Prompt / 代码 / 学习笔记 / 想法）
  -> 进入职业收件箱，保留原始来源
  -> 关联项目、能力主题或职业计划
  -> 必要时主动发起 AI 整理
  -> 人工审核草稿
  -> 回到职业全景，形成过去 / 现在 / 未来的判断
```

每一步都有可见结果。AI 失败时，原始记录仍已经保存；AI 不能覆盖原文，也不能自行发布内容。

## 先不做

- 多 Agent 编排、知识图谱、向量检索和自动能力评分。
- 对链接、文件或历史资料的自动抓取与解析。
- 多人协作、账号体系、可撤销的线上公开作品集和移动端原生应用。
- 任意聊天入口。对话只服务于某次明确的“整理草稿”任务。

这些能力只在“标签 + 搜索 + 项目关联”确实无法满足回看需求后再加。

## 运行边界

- 只在本机运行，默认监听 `127.0.0.1`，不暴露到局域网。
- 项目、资料和分析数据存本地 SQLite；电子简历编辑数据暂存浏览器 localStorage。完整备份会合并两部分数据，附件和网页链接首版只保存 URL。
- 原始记录默认私密。每条记录单独选择“允许 AI 整理”或“禁止 AI 使用”。
- Codex 只接收本次任务中用户明确选中的、允许 AI 使用的记录 ID；它只能生成草稿。

## V0.1 的四个对象

### 职业资料

职业资料是任何可能影响职业判断的原始来源：历史项目文档、Prompt、会议结论、代码仓库、学习笔记、链接或一个方向想法。

首版只记录来源链接或本地路径、简短说明、隐私许可和归属关系；不复制或替代 Get、Notion、Obsidian 的原文管理能力。

### 项目

项目是过程证据的容器，不是待办清单。

必填：名称、背景或目标、我的职责、状态。

可选：结果、复盘、可公开性。

### 职业记录

职业记录是用户主动写下的工作、学习和项目过程；原始记录永远优先于 AI 总结。

必填：日期、原始正文、AI 使用许可。

可选：类型（工作实践 / Prompt-Agent 优化 / 学习笔记 / 自由记录）、关联项目、链接、标签、收获、卡点、下一步。

### 草稿

草稿是 AI 的派生产物，不能覆盖记录。

必填：草稿类型、正文、来源记录 ID、状态（待审核 / 已确认 / 已拒绝）、模型和指令版本、创建时间。

首版只提供两种草稿：`记录整理` 与 `周回顾参考稿`。项目案例草稿等稳定使用后再做。

## 日常怎么用

### 1. 先把职业资料放进收件箱

职业资料可以是一段新经历，也可以是历史项目文档、Prompt、代码链接、会议结论、学习笔记或职业想法。先保留来源和简短说明，不要求一次整理完。

入口提供“记录经历 / 导入资料 / 添加想法”三种选择，最终都进入同一个收件箱。只有需要时才补类型、项目、链接和 AI 权限；不要把入口做成长表单。

### 2. 关联职业地图，再让 AI 帮忙

主按钮是“保存并生成整理草稿”。执行顺序必须是：

```text
保留原始来源 -> 关联项目、能力主题或职业计划 -> 创建整理任务 -> 显示来源 -> 产生草稿
```

用户也可以只把资料放进收件箱。它不是次要失败路径，而是面对历史资料、敏感内容或暂时无法判断归属时的正常操作。

### 3. 只审核一个明确结果

草稿页左边展示原始来源，右边展示 AI 草稿。用户只能做三件事：编辑、确认沉淀、拒绝。

确认后草稿成为可筛选的知识材料；拒绝不会删除原始记录。

### 4. 每周做一次事实回顾

周回顾自动列出本周记录、项目与未完成下一步。用户先手写“完成 / 收获 / 问题 / 下周重点”，再可选生成一份参考草稿。AI 草稿永远在用户手写内容之后。

## 页面与按钮

### 全局壳

桌面端使用左侧导航、中央内容和按需出现的右侧上下文面板。不要把 Agent 对话做成首页。

```text
┌──────────────────────┬─────────────────────────────────────┬────────────────────────┐
│ 个人职业操作系统        │ 当前页面                              │ 仅按需显示的上下文面板    │
│ [+ 添加职业资料]        │                                     │ 本次 AI 会读取的资料      │
│                       │                                     │ 草稿状态 / 来源 / 隐私    │
│ 职业首页               │                                     │                        │
│ 工作资料 / 项目档案     │                                     │                        │
│ 工作记录 / 岗位对照     │                                     │                        │
│ 简历制作 / 内容确认     │                                     │                        │
│                       │                                     │                        │
│ 设置与导出             │                                     │                        │
└──────────────────────┴─────────────────────────────────────┴────────────────────────┘
```

- `+ 添加职业资料`：全局主要入口，提供“记录经历 / 导入资料 / 添加想法”，都进入职业收件箱。
- `待审核`：仅当存在待审核草稿时展示数量徽标，不能把数量当成压力指标。
- `设置与导出`：放在底部，不抢占日常操作入口。
- 右侧面板只在发起任务、审核草稿或查看详情时出现；平时收起，避免仪表盘感。

移动端将左侧导航变成底部五项导航；职业资料录入使用全屏抽屉；来源与草稿通过分段切换，不硬挤双栏。

### 1. 职业首页

首页回答“我是谁、过去做过什么、现在在形成什么、下一步去哪”，不回答“我今天得了多少分”。

```text
职业全景                                  [导入资料] [+ 添加职业资料]
当前职业身份：提示词工程师                            [编辑身份]

过去 / 现在 / 未来
历史信息项目     Prompt 与 Agent 实践     AI 应用工程方向

项目资产                                          [查看全部]
能力主线：Prompt / Agent / Vibe Coding / AI 工程

职业资料收件箱                                     [添加资料]
外部笔记、项目文档、代码仓库、本地文件的来源链接
```

- 主按钮：`+ 添加职业资料`，其次是 `导入资料`；两者都进入收件箱。
- 项目页的就近按钮：`补充资料`，直接带入该项目；不要放“AI 分析项目”。
- 首次空状态只给两个选择：`导入一个历史项目`、`记录一段新经历`。

### 2. 职业资料收件箱

```text
添加职业资料                                            [关闭]
[记录一段经历] [导入资料或链接] [添加职业想法]

[ 原始内容 / 来源链接 textarea ]
[关联项目、能力主题或职业计划 v] [AI 可使用 v]

[进入收件箱]                              [保存并生成整理草稿]
```

- `进入收件箱` 是默认动作；`保存并生成整理草稿` 仅在已有可用内容时出现。
- 同一屏只保留一个珊瑚色主按钮，另一个为描边次按钮。
- `AI 可使用` 是明确的开关，不要藏进设置；切到“禁止 AI 使用”时，主按钮文案变为 `保存记录`。
- 类型切换后只显示对应的提示问题，所有补充字段仍可不填。

### 3. 经历与项目

项目列表按“进行中 / 可沉淀案例 / 待补证据”分组，不按技术标签堆卡片。

```text
RAG Demo                                      [编辑项目] [补充资料]
背景、目标、我的职责

过程证据   知识沉淀   项目复盘
时间线：记录 -> 已确认草稿 -> 记录

目前证明了什么                 仍缺什么
能独立做检索链路实验           缺评估样例、运行结果、复盘
```

- 项目页的高频动作是 `补充资料`，可以是新经历或已有资料来源。
- `生成项目复盘草稿` 只有在至少三条允许 AI 使用的关联记录后出现；点击前必须展示将读取的记录清单。
- 不做进度条和能力百分比；证据数量只作为事实，不作为评分。

### 4. 待审核

```text
来源（只读）                         AI 草稿
8 月 4 日 · 学习记录                 标签：RAG / 文档切分
原始正文与项目上下文                 结论、卡点、下一步

[查看完整记录]                       [编辑] [拒绝] [确认沉淀]
```

- `确认沉淀` 是唯一强调按钮。
- `拒绝` 是普通文字按钮，不使用危险红；它是正常的工作流。
- 显示“本次基于 N 条已授权资料生成”，可展开来源清单；不显示模型思考过程。

### 5. 周回顾

```text
第 32 周
本周事实：6 条记录、2 个项目、3 个待办

我本周完成了什么？       [textarea]
最大的收获？             [textarea]
未解决问题？             [textarea]
下周最重要的三件事？     [textarea]

[保存周回顾]  [基于已填写内容生成参考稿]
```

- `保存周回顾` 是主按钮；`生成参考稿` 仅在已有手写内容后可点。
- 页面开头只显示事实列表，不要把 AI 周报放在第一屏。

## 视觉和交互基线

沿用已有“暖色 Agent 工作台”方向：暖白画布、深墨文字、珊瑚色只用于主动作、少量深色面板用于任务来源与状态。

- 正文优先可读性；页面标题用宋体感衬线，正文用 Noto Sans SC，任务 ID 使用 JetBrains Mono。
- 卡片用浅米色、细边框与留白区分层级，不用大面积阴影、渐变或玻璃拟态。
- 按钮只有三层：主动作（珊瑚实色）、次动作（描边）、低风险操作（文字）。同一屏最多一个主动作。
- 状态不只靠颜色：待审核、已确认、私密、失败都带文字与图标。
- 动效只用于保存成功、任务进度和侧栏/抽屉展开；支持减少动态效果。

## 实施顺序

### 第 1 周：先能记住

实现本地 SQLite 的项目和记录；完成快速记录、项目关联、时间线和 JSON 导出。此阶段不接 AI。

### 第 2 周：再能回看

实现项目档案、资料搜索/筛选和手工周回顾。用真实记录连续使用一周，删掉没用的字段。

### 第 3 周：最后接 AI

接入一个受控的 `整理记录` 任务：明确来源、生成草稿、编辑/确认/拒绝。先不接多资料项目总结。

### 第 4 周：验证习惯

连续使用，记录每次卡住的地方。只有确实高频的阻碍，才进入下一版；优先补项目复盘草稿，而不是加新页面。
