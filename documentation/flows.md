# 关键流程

本文件只记录会写数据、触及隐私或引入外部副作用的流程。

## 创建并关联职业资料

**参与者：** 本机所有者。**前提：** FastAPI 可访问、数据库可写。**结果：** 一条不可被草稿覆盖的原始资料被保存，可选关联一个项目。

1. React 表单校验必填正文和可选 URL，调用 `POST /api/materials`。
2. 浏览器到 FastAPI 是信任边界；后端重新校验正文长度、枚举值、UUID 和 URL，不接收或读取客户端给出的本地路径。
3. service 确认 `project_id` 为空或对应项目存在；不存在时返回 `404 not_found`。
4. storage 在一个 SQLite 事务中写入资料，保存 `ai_allowed` 明确值和创建时间。
5. 前端刷新收件箱与项目证据列表。失败时保留表单输入，并显示可行动错误。

## 切换项目公开状态与读取简历

**参与者：** 本机所有者。**前提：** 项目存在。**结果：** 仅项目本身被标记公开；原始资料仍保持私密。

1. React 调用 `PATCH /api/projects/{id}/visibility`，提交明确的布尔值。
2. FastAPI 校验项目 ID 与布尔值，service 更新 `is_public` 和 `updated_at`。
3. `GET /api/resume` 只读取 profile 与公开项目的简历字段，绝不返回 materials、drafts 或原始 URL。
4. 本地版本的打印使用该 API 响应；任何线上分享必须等后续分享快照能力，不能把完整数据序列化进 URL。

## 导出与导入本地数据

**参与者：** 本机所有者。**前提：** 数据库可读或导入文件已选择。**结果：** 数据可迁移，失败不破坏当前数据库。

1. 设置页请求导出接口读取 SQLite 数据，再合并浏览器中的简历正文、模板和头像，生成完整 JSON 下载。
2. 导入先验证 JSON 结构、ID、关联完整性和字段限制，汇总错误后拒绝坏文件。
3. 有效导入写入同目录临时数据库或临时文件，成功后原子替换，并在替换前创建备份。
4. 导入、覆盖和恢复操作均需前端明确确认；错误响应不包含本地文件系统详情。

## AI 整理草稿（第 3 阶段）

**参与者：** 本机所有者。**前提：** 用户明确选择资料，且每条 `ai_allowed=true`。**结果：** 产生待审核草稿，原始资料不变。

1. React 展示选中的资料标题和数量，提交任务类型与 `material_ids`。
2. FastAPI 逐条查询资料；任何不存在或未授权资料均返回 `422`，不调用模型。
3. service 将限定来源交给模型 integration；模型密钥只在服务端，日志不记录完整原文或 prompt。
4. integration 对模型输出解析与 Pydantic 校验；超时和可重试上游错误最多按配置重试。
5. 成功结果与来源关系写入 `drafts`、`draft_sources`，状态为 `pending`；失败不影响资料。
6. 用户只可编辑、确认或拒绝草稿。确认代表可作为筛选材料，拒绝只改变草稿状态。

## DeepSeek 编码任务

**参与者：** 本机所有者。**前提：** 任务面板显示 dsh、bwrap 和 DeepSeek 凭据均已就绪。**结果：** Agent 仅在固定代码工作区执行，输出与状态可查询、可停止。

1. 浏览器提交任务和可选资料 ID；浏览器到 FastAPI 是信任边界。
2. FastAPI 检查运行时开关与依赖，service 重查资料授权；未授权、重复或不存在的资料返回 `422`，已有运行任务返回 `409`。
3. storage 先写 `queued` 任务记录；部分唯一索引保证一次只有一个 queued/running 任务。
4. Agent runner 使用固定的参数数组启动 dsh，并通过 bubblewrap 将 `data/`、`.env`、日志、PID 与 Git 元数据从 Agent 文件视图中移除。
5. 仅明确选择的资料正文会附在任务提示中；DeepSeek API key 只由子进程环境读取，绝不回传浏览器。
6. 页面轮询状态；用户停止时只杀死匹配任务的受管理进程组。完成/失败/超时写入状态、退出码和截断输出。
