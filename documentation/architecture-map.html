01 · 系统全景

从浏览器到本地数据库

职业工作台

Vite + React。页面渲染、用户交互和本地简历偏好。

App Shellfrontend/src/App.tsx路由、共享数据、应用框架业务页面frontend/src/pages/按项目、资料、岗位等业务域拆分电子简历frontend/src/resume/专属 UI、拖拽顺序、本地头像

本地 API

FastAPI。验证输入、调用业务规则、保持统一响应格式。

Application Shellbackend/app/main.py生命周期、中间件、错误处理、路由注册Route Modulesbackend/app/routes/按业务域拆分 HTTP 入口Career Servicebackend/app/services.py共享业务规则和数据访问编排

可信数据

单机 SQLite。原始资料私密，只有公开项目进入简历读取。

Storagebackend/app/storage.py表初始化、种子数据、SQLite 边界career-os.dbdata/career-os.db本地职业资产数据库Input Schemasbackend/app/schemas.pyPydantic 校验与字段约束

运行边界：浏览器只通过 /api 调用本地后端；网页不直接读取 SQLite，也不直接执行 Shell。职业资料默认私密，公开状态仅影响电子简历读取。

02 · 前后端模块如何对应

名称一致优先，职责一致优先于目录镜像
用户看到的板块前端模块后端模块为什么这样拆
电子简历resume/routes/resume.py名称完全一致；后端只读取职业档案与公开项目。
项目中心pages/Projects.tsxroutes/projects.py项目创建、更新、公开状态都在同一业务域。
职业资料收件箱pages/Library.tsxroutes/materials.py前端用产品语言“收件箱”，后端用数据实体 materials。
职业 Git / 待审核CareerGit.tsx + Review.tsxroutes/career.pycommit 与 draft 都属于职业记录沉淀，不重复拆一层服务。
目标岗位pages/Opportunities.tsxroutes/opportunities.py岗位保存与显式 AI 分析是一条机会评估链路。
设置 / 编码任务pages/Settings.tsxroutes/agent_runs.py设置是入口页；Agent 是独立的受控运行能力。
职业全景 / 能力地图Overview.tsx + Capabilities.tsx组合读取多个领域它们是聚合视图，不创建没有独立实体的伪后端模块。

03 · 核心数据流

以“项目进入电子简历”为例
01 / INPUT

创建项目

Projects.tsx 通过 api.ts 提交项目表单。

02 / VALIDATE

路由验证

routes/projects.py 使用 Pydantic schema 验证输入。

03 / PERSIST

写入职业资产

CareerService 调用 Storage 更新 SQLite。

04 / SHOW

选择公开展示

resume.py 只查询 is_public = true 的项目。

安全设计：关联资料、草稿、来源 URL 不会经由 GET /api/resume 返回。AI 分析也只有在用户明确勾选并点击后才会执行。

04 · 文件地图

展开查看每个目录的职责
frontend/src/ — 界面与交互
  • App.tsx — 应用壳、hash 路由、共享上下文
  • api.ts — 唯一 HTTP 客户端与 API 类型
  • pages/ — 可独立访问的业务页面
  • components/ — 跨页面复用 UI 和弹窗
  • resume/ — 简历页面、专属样式、localStorage 偏好
  • types.ts — 页面共享上下文类型
  • styles.css — 全局设计 token 与基础样式
backend/app/ — 本地 API 与业务规则
  • main.py — FastAPI 壳、生命周期、中间件、错误处理
  • routes/ — 对外 HTTP 接口，按业务域分文件
  • services.py — 跨路由共享的业务规则
  • storage.py — SQLite 初始化和持久化边界
  • schemas.py — 输入校验模型
  • advisor.py — 岗位分析的受控 AI 调用
  • agent.py — 固定工作区的编码 Agent 运行管理
documentation/ — 持久化设计说明
  • architecture.md — 可搜索的文字架构说明
  • flows.md — 业务流程
  • permissions.md — 数据与权限边界
  • tests.md — 已覆盖的验证场景
data/ — 单机持久化数据
  • career-os.db — SQLite 数据库
  • JSON 导出由 GET /api/exports/career-data 提供

05 · 设计原则

为扩展留边界，不为想象中的需求加层
01 / DOMAIN FIRST

按业务域拆

项目、资料、简历、岗位各自聚合；共享规则继续留在 Service，避免只为目录镜像产生空模块。

02 / LOCAL FIRST

数据在本机

SQLite 是唯一业务数据源。浏览器 localStorage 只保存头像和模块排序等展示偏好。

03 / EXPLICIT CONSENT

用户主动授权

公开项目才进简历；资料需要明确允许才可随 AI 分析发送；网页不执行任意命令。
