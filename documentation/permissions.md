# 权限边界

## 当前角色

首版只有一个本机所有者。应用仅监听 `127.0.0.1`，没有账号、Cookie、token 或远程访客；因此所有写接口都由本机所有者使用。这个结论依赖本机网络边界，不能直接用于公网部署。

| 资源 | 操作 | 本机所有者 | 外部访客 |
|---|---|---:|---:|
| profile、projects、materials、commits、weekly_reviews | 读写 | 允许 | 不存在访问路径 |
| JSON 导出/导入 | 执行 | 允许，且覆盖前确认 | 不存在访问路径 |
| drafts | 查看、确认、拒绝 | 允许 | 不存在访问路径 |
| 原始资料 | 作为模型来源 | 仅 `ai_allowed=true` 且本次明确选中 | 不允许 |
| 电子简历 | 本地读取/打印 | 仅公开项目字段 | 不存在线上路由 |
| DeepSeek 编码 Agent | 启动、查看、停止 | 仅固定 `growth-os` 工作区，且一次一个任务 | 不存在访问路径 |
| DeepSeek 岗位分析 | 手动发起匹配 | 仅发送本次勾选项目与 `ai_allowed=true` 的资料 | 不自动执行 |

## 服务端强制规则

- `is_public` 只控制 `/api/resume` 中项目简历字段是否出现，不会公开关联资料、草稿、来源 URL 或联系方式以外的字段。
- 草稿请求不得信任客户端的“已授权”标记，必须由服务端查询 `materials.ai_allowed`。
- 导入、恢复、删除和覆盖属于破坏性操作，要求显式确认、事务或原子替换，并记录安全日志。
- 不接受浏览器给出的文件路径作为读取或命令执行目标。URL 仅作为文本资料保存。
- 编码 Agent 的资料授权由 `materials.ai_allowed` 服务端重查；代码工作区由 server 固定，`data/` 和 `.env` 由 bubblewrap 隐藏。
- 岗位描述只作为不可信文本保存；系统不会自动访问招聘链接、抓取网站、投递职位或创建定时分析。DeepSeek 仅在用户点击“开始一次 AI 匹配分析”时调用。

## 升级条件

一旦服务监听非 loopback 地址、支持线上分享或存在第二位用户，必须先加入认证、资源所有权字段、会话保护、最小 CORS 规则和服务端授权检查；此文档需改为角色与资源矩阵，不能沿用“本机即所有者”。
